# frappe-todo

A todo app as a monorepo: a **Next.js 16** frontend and a **Frappe v16** backend on **MariaDB**, talking over Frappe's **REST API**.

```
Browser ──► Next.js :3000 ──── REST (server-side) ────► Frappe :8000 ──► MariaDB :3306
              │                                             └─ Redis (started by bench)
              └─ httpOnly cookie holds Frappe's session id
```

- The browser only ever talks to Next.js. Server Components and Server Functions call Frappe's REST API from the server, so there is no CORS, no API keys in the browser, and the Frappe session id sits in an httpOnly cookie that JavaScript can't read.
- Login is Frappe's own session login (`POST /api/method/login`). Any Frappe user can sign in.
- Each user sees only their own todos: the `Todo Item` DocType grants the `Todo User` role create/read/write/delete **if owner**, and Frappe enforces that on every REST call.

## What you need

### Tools

| Tool | Version | Why | macOS install |
| --- | --- | --- | --- |
| Node.js | **≥ 24** | Frappe v16 builds assets and runs socketio with it. Next.js alone needs ≥ 20.9. `.nvmrc` is provided | `nvm install 24`, or `brew install node@24` |
| Python | **3.14** | Frappe v16 pins `>=3.14,<3.15` | `brew install python@3.14` |
| uv | recent | bench installs Python packages with it | `brew install uv` |
| bench | recent | creates and runs the Frappe bench | `uv tool install frappe-bench && uv tool update-shell` |
| yarn | 1.x | Frappe's asset build | `npm install -g yarn` |
| MariaDB | 11.8 | the database | `brew install mariadb@11.8 && brew services start mariadb@11.8` |
| Redis | 6+ | Frappe cache, queue, realtime (bench starts its own instances) | `brew install redis` |
| pkg-config, mariadb-connector-c | – | build the `mysqlclient` driver | `brew install pkg-config mariadb-connector-c` |
| git | – | bench clones Frappe | Xcode command line tools |

`wkhtmltopdf` is only needed if you generate PDFs; this app doesn't.

Staying on an older Node? Set `FRAPPE_BRANCH=version-15` in `.env` (Python 3.10 to 3.14, Node ≥ 20.9). The app code works on both; v16 is the default because it's the current release.

`npm run doctor` checks all of the above and prints the exact fix for anything missing.

### Environment variables

Everything lives in one root `.env` (copy `.env.example`). The setup scripts read it directly and `apps/web` loads it through `dotenv-cli`.

| Variable | Required | Default | Used for |
| --- | --- | --- | --- |
| `FRAPPE_ADMIN_PASSWORD` | yes | – | Password of the site's `Administrator` (Frappe desk login) |
| `MARIADB_ROOT_PASSWORD` | yes | – | bench logs in as MariaDB root once to create the site's database and user |
| `MARIADB_ROOT_USERNAME` | no | `root` | ↑ |
| `FRAPPE_SITE_NAME` | no | `todo.localhost` | Site name; the web app also sends it as `X-Frappe-Site-Name` |
| `FRAPPE_BRANCH` | no | `version-16` | Frappe branch bench clones |
| `DEMO_USER_EMAIL` / `DEMO_USER_PASSWORD` / `DEMO_USER_NAME` | no | `demo@example.com` / – / `Demo User` | Demo end-user (role `Todo User` only). Leave the password empty to skip |
| `FRAPPE_URL` | no | `http://127.0.0.1:8000` | Where the Next.js **server** reaches Frappe. Never sent to the browser |
| `PORT` | no | `3000` | Next.js port |
| `MYSQL_UNIX_PORT` | no | `/tmp/mysql.sock` | Only if MariaDB's socket lives elsewhere |

Use `127.0.0.1` rather than `localhost` in `FRAPPE_URL`: Node may resolve `localhost` to `::1`, where Frappe isn't listening.

## Quick start

```bash
cp .env.example .env        # then set FRAPPE_ADMIN_PASSWORD, MARIADB_ROOT_PASSWORD, DEMO_USER_PASSWORD
npm install
npm run doctor              # fix anything it reports
npm run setup:api           # bench init, create site, install todo_app, create demo user (a few minutes)
npm run dev                 # Frappe on :8000 + Next.js on :3000
```

Then open <http://localhost:3000> and sign in as the demo user. Frappe's desk is at <http://127.0.0.1:8000/app> (user `Administrator`).

`setup:api` is safe to re-run: it skips whatever already exists.

MariaDB's Homebrew root account has no password. Give it one (and put the same one in `.env`):

```bash
mariadb -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED VIA mysql_native_password USING PASSWORD('<password>'); FLUSH PRIVILEGES;"
```

## REST API

The backend's API is Frappe's REST API. The essentials:

| Action | Request |
| --- | --- |
| Log in | `POST /api/method/login` `{"usr","pwd"}`, sets the `sid` cookie |
| List | `GET /api/resource/Todo%20Item?fields=[…]&filters=[…]&order_by=…&limit_page_length=…` |
| Create | `POST /api/resource/Todo%20Item` `{"title","priority","due_date"}` |
| Update | `PUT /api/resource/Todo%20Item/TODO-00001` `{"status":"Done"}` |
| Delete | `DELETE /api/resource/Todo%20Item/TODO-00001` |
| Who am I | `GET /api/method/todo_app.api.me` |
| Counts | `GET /api/method/todo_app.api.stats` |

Full reference with curl examples, token auth and error shapes: [docs/API.md](docs/API.md). Ready-made requests: [apps/api/http/todo-item.http](apps/api/http/todo-item.http). The web app exposes one endpoint of its own: `GET /api/health` (web up? can it reach Frappe?).

## Working on the backend

- **DocType**: `apps/api/todo_app/todo_app/todo/doctype/todo_item/`. `setup:api` enables `developer_mode`, so editing the DocType in the desk writes the JSON straight into the repo (the app is symlinked into the bench). Editing the JSON by hand? Bump its `modified` timestamp, then `npm run migrate`.
- **New field?** Add it to the DocType, then to `apps/web/src/lib/types.ts` and the `FIELDS` list in `apps/web/src/lib/frappe/todos.ts`.
- **Business rules** go in `todo_item.py` (`validate`). They run for every client: the web app, the desk, and raw REST calls.
- **Custom endpoints** go in `todo_app/api.py`, decorated with `@frappe.whitelist(...)`, and are served at `/api/method/todo_app.api.<name>`.
- Tests run against the dev site (`allow_tests` is switched on for it) and roll back after themselves.

## Design notes

- **Why Next.js sits between the browser and Frappe.** Frappe's `sid` cookie and desk share `localhost` with the web app (browsers share cookies across ports), and cookie-authenticated writes need a CSRF token that only Frappe-rendered pages get. Keeping Frappe's session id server-side, under a different cookie name (`todo_sid`), avoids both problems. Server Functions add Next's own origin check on top.
- **Why `setup.sh` doesn't use `bench get-app`.** `bench get-app <path>` requires the app to be its own git repository, which doesn't fit a monorepo. The script symlinks `todo_app` into the bench, installs it editable and lists it in `sites/apps.txt`, which is what `get-app` does.
- **Site selection.** `bench use` pins the dev server to `FRAPPE_SITE_NAME`; the `X-Frappe-Site-Name` header covers setups where it isn't pinned.
- **Not included yet:** sign-up, 2FA (login says so if the account needs it), pagination beyond 100 items, production deployment (Frappe behind nginx/Caddy, Next.js via `next start`).

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Web app shows "Couldn't load your todos" | Frappe isn't running or `FRAPPE_URL` is wrong. Check `http://localhost:3000/api/health` |
| `npm run doctor`: Node too old | Frappe v16 needs Node ≥ 24 (`nvm use`, reads `.nvmrc`) |
| `bench init` fails midway | `rm -rf apps/api/bench` and re-run `npm run setup:api` |
| Can't log in to the desk as Administrator | It's `FRAPPE_ADMIN_PASSWORD` from `.env` at site-creation time. Reset: `cd apps/api/bench && bench --site <site> set-admin-password <new>` |
| Login loops in Safari on a production build | `next start` marks the cookie `Secure`, which Safari refuses over plain `http://localhost`. Use Chrome/Firefox, or serve over HTTPS |
| Port 8000 / 3000 busy | Stop the other process; for Next.js set `PORT` in `.env` |
